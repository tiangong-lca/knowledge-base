## 全书的著作形态

2026-11-06新增的用户要求适用于整个目标、全部既有与未来正文，具体配额、内容守恒与输出要求见 `_docs/lca-book-goal.md` 第2.7—2.12节。全书必须有中心问题、问题转换、竞争解释与有条件的结论；每部、每章及章际承接都为这一论证服务。优先单卷6—8部、每部3—7章、全书24—32章；只有实际篇幅与论证容量证据支持时才提出多卷。原八个研究领域和十二组附录责任继续完整保留，不固定为八本书。

书籍目录用部—章—节显示骨架。章题采用短名词短语，避免疑问句、“怎样／如何／为什么／谁／什么”和“从……到……”句式；节题不用完整判断句或算例步骤。每章正式目录3—5节，全书不超过120节。详细字数、句式和标点检查沿用目标文件，不能通过删除困难内容或强行合并达标。37章和5专题每项均须在旧新映射中有归宿；五专题并入正文或进入分工明确的附录／方法附记。

前言写成连贯散文；导览重写为约1—2排版页的导论或阅读指南，阅读路线不逐条进入正式目录。正文须有实际推理、节奏和作者判断，保持问题与结论的阅读次序。不能把来源摘要或网页段落简单拼接；仅改题、缩小可见目录或隐藏层级不算完成。作者声音不得依靠虚构经历、人类身份或专家审定；科学限定、相反证据和未知随对应论断保留。

## 正文、注释和开发文档

正文说明对象、问题、证据、推导、反例及结论，采用读者可以连续理解的叙事。已经交付的章节须作为完整阅读单元成稿，不显示研究波次、建设状态、任务编号、代理活动、工具运行、构建/测试状态、核查日志、内部主键或未来实施待办。不得仅把“草稿”改成“正式”来冒充完成。

新写、修订和审读中文书章时，遵循[写作与教研指南](editorial/readable-writing-and-teaching.md)。明确读者应能解释或判断什么，用具体对象和可跟随的推理组织正文。说明数字、公式和案例如何支持判断，保持案例设定和静态阅读所需信息完整。章法由历史解释、方法争论、数学推导或案例的实际任务决定。

影响结论含义、适用范围或推断强度的条件，放在正文对应论断附近。只供精确查证的细节可放入读者可达的注释或附录。项目过程文字归入 `_docs/`。保留对理解有帮助的历史作者计划、方法本身的研究程序和实际文献冲突。作者提出的分析建议要保留其归属和建议性质。

来源、版本、引文位置、相反证据、实际适用范围、虚构数值、缺失数据和未传播的不确定性仍须清楚可查。一般编写/审阅身份在编写说明中交代一次，独立的打印合订本也保留一份相同说明；特定论断需要的限定随该论断保留。来源可取得、文件哈希或软件检查不能替代科学判断，也不得暗示人类专家已审阅。

开发记录保留实际检索协议、原件取得与读取范围、失败记录、结构修订前后对照、审查发现及处理、测试与交付回执。迁移不得销毁这些证据。底层结构化记录继续接受完整性检查；公开阅读页和书目导出只提取书目、引文与解释所需的信息，不把研究工作台直接呈现为书页或公开AI阅读资料。开发 Markdown 不进入网站正文、搜索语料或公开 AI 阅读索引。

正文保留核心推理、代表证据、重要异议以及影响使用的条件；逐项复算、版本异文和细部考证可依审阅记录移入注释、方法附记或附录。转层后仍须读者可达，不能以后台留档代替公开结论的关键条件。网站专题只有具备独立用途才另行保留，不作为所有未选材料的堆放处；共享科学记录不要求网站与书籍展示成员永久相同，但当前注册守卫的有界扩展须另行实际验证。

共同点与分歧围绕同一问题呈现，先对齐对象、用途、版本和证据。局部来源相容、制度规定、经验验证、价值取舍和未解冲突不能混称“共识”。读者应能识别本书为什么作出某项有条件判断，而不只是看到几位作者并列发言。来源证据不对称时不制造平衡；真实反对意见不能为流畅而消失。

## 阅读顺序与引注

作品名为《生命周期评价的前世今生》；天工 LCA 知识库是网站身份。导航、标题、打印与引用说明保持这一区别，不以不同工作名称代替作品身份。

网站首页章节、侧栏与移动目录在网站导航内部保持一致。书籍使用独立编排的部—章—节目录、连续阅读与打印顺序，可以比网站更粗；不再要求书籍顺序等同于网站页面树。两种结构共享规范正文、论断、证据、案例和版本，避免复制后漂移。书籍编排须有显式顺序与完整迁移映射，不能从文件枚举偶然生成。

当前 `config/book-edition.json` 显式登记混合书籍编排：共享前言和阅读导论、保留的原正文／专题、独立成文的“框架职责”“共同生产”“气候当量”“数据适用性”和“可修订的判断”章，以及三篇计算附录，共39个阅读单元。框架书章交错使用原两页的规范正文，实际替换其两个打印单元，拥有一次连续注释；网站仍保留细分页面。“清洁生产的期待”保留一份网站与书籍共享的真实章源，按三节成文；五个原命题及旧注身份保留，新增的发展议程另有规范记录和第六注。“功能参照”将C08与S03的解释写成共同章源，一次连续编排17条规范论述；网站仍保留面向数据字段的细入口。原15条身份和八块普通解释均有显式去向，新增维护与记录/模型解释各有身份。“交换语义”将C18、S02、S05整合为四节共同章源，保留56个原身份及14块普通内容责任。历史专题S01仍保留六块普通解释和APOS段，八个已移至实际书章的规范段在打印中改为具名交叉引用；它不是被整页消费或已经完成附记。不同单元是否需要独立装配，由实际论证与分节决定。B25已将C14/C15写成四节14注的共同书章，两个细页各保留七条规范段落。当前32章和157节只是实际数量，全书成文与120节终稿要求仍未完成。后续迁移须同时验证书籍章节边界、书章内连续注号、交叉引用、目录／打印层级、稳定链接及旧版引用；组合多个网页时不能原样拼接各页注号。网站导航列表本身不充作书籍正文；共享前言和导论须已写成连续散文才进入打印。全书目标与未收录范围仍由开发文档和任务记录维护，不以内容数量伪造完成比例。

每章的实质段落至多一个可见注号，同章跨组件连续编号；重复引用同一论述复用该章的同一注释。注号指向本章注释，注释给出来源、位置和必要限定。概念索引用可展开的“出处与条件”；全书论述汇集页以论述本身定位，不能另造一套与章内注号相混的全局“注释”编号。内部 `cl-`、`ev-`、`rd-`、案例 ID 和哈希可以保留在锚点、数据和内部回执中，不作为正文的阅读标识。打印合订本的锚点必须唯一，章与节的标题层级必须区分。

## 与 docs 站点一致的版式

参照拥有者为 workspace 的 `docs` 子项目，当前事实以其契约、安装版本源码和实际渲染为准。使用相同的 Fumadocs 文档网格、侧栏、目录、中文控件、字体层级、移动导航和明暗主题。首页72rem外框不等于文档网格宽度，禁止再次将它全局写入 `--fd-layout-width`；禁止再叠加独立42rem正文上限。

变更须比较同视口下的实际几何关系。此次基线在1440px视口下：参照正文约825px，文章容器889px，左右内边距各32px，侧栏与目录各268px。不是把数字永久硬编码为所有尺寸；应保持参照站实际响应规则，在390、1440、1633、2048和2560px及明暗主题核验。文档页不叠加第二套外部页头或移动目录。

## 独立判断与验收

文献支持、科学含义、读者理解、软件完整性和视觉呈现分别检查。内置子代理适合有界的实现和检查。本地 DeepSeek Harness 可按 workspace 约定提供独立初评或具体分歧复核。重要阅读形态变更应有新上下文的读者评估，不能仅凭测试通过交付。全书评估须通读实际稿件，检查目录是否呈现论证弧线、正文是否兑现章题及章间承接、42项映射是否守恒，并将结构统计与实际理解分别报告。

独立读者还须检查：删除某段或案例会失去什么必要解释或反例；正文、嵌入工具和相邻章是否重复；共同基础、真实分歧和未知是否可辨；章节是否给出正面所得。局部清晰不能推定部级或全书的论证完成。每个完成的部须连续回看，正式版次再检查全书实际稿件，并记录审读范围。

使用 DeepSeek Harness 时按适用 workspace 约定实际核验任务工作目录、模型、思考强度和权限。当前要求为 DeepSeek V4.1 Flash Max、Max 思考及完全权限。无法核验或使用所需配置时，记录具体限制。新建独立会话，默认只读，提供中立的任务、具体工件与版本、验收条件和所需输出，初评不提供主评结论。主评者核对发现的具体位置、触发条件和影响，依据来源、复算或浏览器证据裁定，并复核后续改动影响到的发现。评审记录说明实际覆盖范围。人类专家认证及真实读者试读分别依据实际发生的活动记录。

修改数值案例正文时同步维护其模板与规范记录，保持公开输入哈希及实际数学含义；审查完成后才发布。校验器应针对重复注号、错误阅读顺序、过程性正文、可见内部编号等真实缺陷，同时允许科学不确定性和历史研究对象的正常表述。语义和真实浏览器检查始终必要。

当同一作品的证据来自不同载体时，注释和引文详情须保留到实际引用载体的入口。网页书目或修订目录不能统一跳到该作品的主PDF；原始PDF、电子表格、网页和仅有文字摘录也不能互相冒充。具体载体入口与作品书目入口可以并列，但不重复制造独立来源。

## 引用连续性基线

2026-11-07的迁移以Main `dd715663c3438aa730eef0da1696dc376a7715f1`实际编译输出为基线：44个网页、42个原打印单元，共2254个旧章节、标题与注释地址。可见注号仍按当前单元首次出现连续编号；新的规范锚点绑定单元与主张身份，不能再以显示序号充当身份。旧地址保留同一主张的本地别名，或给出可在无脚本环境使用的明确迁移链接。标题改名保留旧ID；前言、导论的旧主题位置用不进入目录的语义位置标记。

基线清单及其源身份由独立代码摘要约束，打印前置顺序也有独立检查。新增附录必须在当前配置中显式登记；运行时与导出再分别对照实际发现的正文源文件，防止配置与输出同时漏掉同一个新页面。容器章六段细算迁入附录后，旧注号保留原观点的原生迁移链接和打印别名；旧细算标题提供具名附录入口。生成与导出不得仅对照同一份可删改清单而共同漏项。每个旧注释必须核对实际所指主张，不能只检查地址存在。共有主张在不同打印单元有不同锚点，同一单元复用注释。

旧数字地址可能在更早的未标版网页中另有含义。没有版次的hash不能还原这种区别：旧地址说明须明示本次保留日期并提供不可变源码入口，不声称存在未经验证的托管历史版。主张的实质含义若被撤回或替换，应给出勘误和历史身份；保留ID本身不证明含义连续。后续完整书籍编排仍需逐项验证章边界、注号、链接和正文守恒。


2026-11-07的后续检查发现：开篇交付新发布的规范注释锚点，也必须在段落迁移时保留，不能只检验更早的数字注号。`citation-history.json`因此另行绑定已发布Main a36597d的实际规范注释、非空注释组和打印单元，共1,788个地址，与原2,254个地址一并核验。它来自不可变源码、当时的实际段落出现位置及渲染算法重建，不冒充取得过历史HTML。每条迁移提示保留自己所属版本的日期与不可变源文件入口；不能用较早数字注号基线的出处替代较晚规范地址的出处。

这些冻结记录不自动包含以后新发布的全部地址。改换书章或打印作用域之前，须补齐实际已发布地址的去向和资格，尤其是按原网页作用域生成的打印标题名；不能把当前旧数字标题的目标检查当成对这些名字的永久保护。页面、注释、书章和版次各有身份，完整性检查必须覆盖实际发生变化的层次。

旧单元或注释组的地址还代表原来的内容范围。两页合成一章或细页新增段落时，仅把旧组地址留在新完整注释表上并不充分：应在该原生目标提供原文标题、版次及原注释子集的精确链接，说明新章还有其他内容。原地址与当前原生目标相同时，范围说明附在原生目标内；移走的范围使用无需脚本的分流说明。新增规范正文、旧普通解释的实质和具名导航均须接受实际文本检查，不能只核对注号或链接存在。

单个既有章节新增命题时，同样须保留旧章与注释组原有的范围；不因网址和原生ID未变就把原范围扩大；例如，不能把旧八注无说明地解释成新的全部十注。新增说明和旧命题分别登记，原注的实际去向、读者可见的版次范围与完整正文共同核验。


保留注释地址时，还须核对实际显示的条件、限定、来源与位置、引用载体、前提和案例输入入口。完整源记录不能替代输出中的注释正文，空锚点也不代表引文含义得到保留。普通解释迁移或暂留时，具名导航的文字、真实目标和所在节均属阅读责任；打印中的本地目标应按实际编排转换。
