# 交付给读者的是书稿

## 交付态正文洁净与过程留痕分离（2026-11-20 生效，任务 #166）

依据 `_docs/lca-book-goal.md` §2.15，自 2026-11-20 起全站所有公开构建与后续全部迭代强制执行**过程留痕与公开呈现双层分离**：

- **正文与打印页只出现最终交付版**：默认生产构建（`READER_EDITORIAL_HISTORY !== '1'`）下，`/docs/book/**` 与 `/print/` 严禁渲染开发迭代过程控件——包括 `[data-copyedit-history]`（“此处在 … 版题为……”）、`[data-*-history]`（“… 版「…」的引用范围”）、`[data-part*-reread-part]`（部首导言历史披露）、`[data-legacy-scope]`（可见旧范围框）及 `[data-*-correction]`（章末内联修订条）。旧外部引文锚点（`LegacyCitationAliases`、`[data-legacy-notice]`）仅以 `:not(:target)` 不可见锚点保活，零断链且零视觉干扰。
- **过程留痕完整保真与 `/changes/` 自动汇总**：全部 `config/reader-*.json`、`_docs/editorial/` 写前协议与 `review-evidence/` 三路审稿证物继续 100% 留存以辅助后续撰写与审计；公开 `/changes/`（版本与勘误）页面由 `scripts/reader-changes-ledger.mjs` 自动汇总全部既有迭代的完整修订清单、具名更正说明、部首导言变更及 Git 源码链接。
- **审校预览与 CI 洁净门禁**：本地对照历史可显式使用 `READER_EDITORIAL_HISTORY=1`；默认生产输出由 `scripts/reader-surface.mjs` 的 **Clean-Delivery Gate** 强制拦截，断言所有正文与 `/print/` 页面的过程态控件计数严格为 `0` 且 `/changes/` 汇总齐全。以下历史任务段记录了此前各单元的科学内容交付与审校档案，其中曾提及的“内联历史范围控件／内联更正条”在公开交付态下已统一迁入 `/changes/`，仅在 `READER_EDITORIAL_HISTORY=1` 审校态下显式展开。

## 整合修订优先于追加（2026-11-21 生效，任务 #189）

依据 `_docs/lca-book-goal.md` 第2.16节，自2026-11-21起：

- **新内容融入论证。** 比较、证据和纠错放在读者产生相应问题的位置，与前后段一起推进本节论证。不在节末或章末集中追加独立段落，不用“全书第某部已经表明”“本书统一……”之类的总结和自我说明代替推理。
- **旧段落不享有永久席位。** 可改写、合并、拆分、转入注释或表格，也可删除。论述条数、旧原文和段落顺序不是验收边界，不得把“零改动”“总数守恒”报告为质量证据。章节数约束（每章3—5节、全书不超过120节）、案例数值身份和引用历史继续有效。
- **留痕与可达。** 每项改写、合并、转层或删除，都在单元记录中登记旧→新去向、理由和受影响的前提与消费者，并在 `/changes/` 给出读者能看懂的说明。旧注释与旧地址按本文第一节的不可见锚点或明确迁移保持可达。自 2026-11-21（任务 `#192`）起，历史 41 个单元已收口为经审定的可复核检查点（`config/readable-book-checkpoint.json`，完整历史由 `node scripts/verify-checkpoint-history.mjs` 独立复验），后续整合修订通过 `config/revisions/` 声明改写、新增与论述退役，旧注释地址由共享辅助函数自动改指继任注释或章节说明并在 `/changes/` 公开汇总。
- **独立读者连续读全章。** 新上下文的读者须连续读完整章，回答本章的问题、各节推进、重复与可删段落、需要回读的位置，以及结论是否由正文推出。工程与计数检查另行报告，不能替代这一判断。部级与全书回读须通读实际稿件并据此修订；只做元数据或用词整理的，不称为连续回读。
