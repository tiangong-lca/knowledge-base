# 用户要求与评审分工

用户要求排版参照 docs.tiangong.earth，最终页面采用成稿叙事，所有研究/开发过程文档放在项目开发 Markdown，并在适当节点使用技能和独立判断。此要求落实在 reader-publication-contract.md、AGENTS、编辑/出版契约与 Docpact 路由中。完整著作目标仍由任务#9维护，已保存而未发布的深化稿#20须先与本修订协调。

使用 frontend-design 对照既有站点，采用 doc-coauthoring 的独立读者检验与 webapp-testing 的真实浏览器验证。布局、引用顺序、规范文字和源语义分别检查；没有把软件通过当成书稿或科学结论合格。

## 本地 Claude Code 独立初评

新会话仅先执行 pwd，确认与主任务相同的 workspace 根目录；界面实际显示 Fable5 / 1M / Max 与 Bypass permissions。输入提供实际已发布源码544dc239（等价head9af8b757）、只读docs参照8a94b380和用户要求，没有提供主任务方案或其他评审结论。评估非修改，未授予Git/GitHub写入或运行资源权限。

评审识别了可复核的问题：

- 同一1440px视口，原站正文552px，docs参照825px；全局72rem网格和42rem正文上限是叠加约束。主任务独立测得相同宽度。
- 注号在不同Prose组件中重新从1开始；一章有重复“注1”。
- 首页、额外移动目录、打印使用文件枚举，而侧栏使用meta页面树，阅读顺序不一致。
- 重复章首/章尾核读状态、公开研究工作台、覆盖进度、构建记录和内部主键让书稿呈现为开发过程。
- 打印内容和标题层级需要明确书稿成员与补充专题；中文控件和作品身份需要一致。
- 不能为消除过程叙事而删除虚构数据、无概率的θ范围、构造容差、源版本/勘误、历史事件身份及文献内部矛盾等承重限定。

处理：恢复标准文档网格和中文控件；章级注号与统一页面树；正文连续呈现；公开辅助页改为书目、引文、概念与勘误用途；原过程材料保存在本目录；特定限定进入相应注释。关于论证深度的意见仍用于后续著作扩展，不能以本次排版/措辞修复宣称全书已经完成。

## 独立语义与代码复核

语义复核对照基线检查Claim类型、关联证据、前提、数值事实、案例输入和已用引用的保留情况。发现并修复：

1. 墙面服务期间模板的值本来已含区间括号，改写时再次加括号产生嵌套区间。现改为直接显示原占位符，规范正文为[0,10)，独立复核确认。
2. 迁出通用appraisal显示后，1997分配论文的已知勘误及不采用式16–18的限制丢出阅读面。现将勘误DOI10.1007/BF02978499写入书目版本，并在相应公平论证注释中明确保留限制；复核确认。

代码/信息结构复核发现并修复打印章末“注释”标题与章标题同级的问题：打印时注释用h3，普通章节用h2。还指出公开AI索引和research.json仍会带出旧研究工作台，要求以明确的读者书目投影视图替换，并保留底层完整研究记录。最终导出与浏览器核验随交付记录保存。

这些结果来自代理源语义、代码及读者检查，不是人类领域专家认证。每项实际后续验证及最终交付状态由任务#21/对应PR记录。

## Browser keyboard correction

真实移动端检查发现标准目录在按钮获得焦点后未处理Escape；普通按钮关闭仍可用。安装版本Fumadocs16.17.10的Drawer使用Presence，并无Escape处理。通过公开sidebar hook增加仅限drawer模式的关闭与外部触发按钮焦点恢复；嵌套搜索/菜单先处理自身Escape，桌面折叠状态不受影响。修复后的浏览器复核属于最终交付检查。

## 修订后本地应用复查

Claude Code再次核对实际候选与静态页，确认布局、章内注号、主要阅读面和树序已经修复，并提出剩余问题：概念页的全局跳号与章内注号冲突；打印件缺少版次级编写/引用范围说明；来源使用与保存限定应以简洁读者文字恢复；限制段落标点相连、目录条目和术语有不一致。

据实际代码处理：概念定义改用可展开出处，全书论述汇集去掉全局“注释N”；编写说明在版本页与打印合订本各保留一次，明确具名选段、不暗示全书核读、AI辅助与非专家评审；来源权利和保存条件改写为简洁说明并进入书目数据，执行记录仍留开发文档。恢复具体IPCC非通用默认限定、情景概率的谨慎否定和教学容差非独立实证准则；规范段落标点、前言命名和打印目录。可选段落回链不列为本次阻塞；章节论证深度继续在既有著作任务中处理，不以版式修复冒充著作完成。
